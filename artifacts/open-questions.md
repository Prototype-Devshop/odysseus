# Open Questions: Media Generation Provider Layer

> Companion to [`plan.md`](plan.md) and [`task-list.md`](task-list.md).
> Status values: `open` / `proposed` / `resolved`. Architect records; Forge/Infra/human decide.

**All nine questions were resolved by the human on S2 kickoff.** Decisions are captured in the table's Status/Decision and applied to the plan/task list. The S2 slice is implemented against OQ-1, OQ-2, and OQ-7.

| ID | Question | Why it matters | Decision (human, S2 kickoff) | Owner | Status |
|----|----------|----------------|------------------------------|-------|--------|
| OQ-1 | What is the **source of truth** for the media model registry — the proposed `MediaModel` shape from the brief, the existing `ModelEndpoint` rows (`model_type="image"`), or a hybrid? | Determines how `list_media_models`/default resolution read data and whether existing image endpoints are auto-included. Affects every later slice. | **Hybrid.** Reuse existing image endpoint concepts where helpful, but add a lightweight media registry carrying `provider`, `capabilities`, `workflowPath`, `enabled`/`isDefault` flags, and `kind`. Do **not** force ComfyUI into OpenAI-compatible `ModelEndpoint` assumptions. | Architect + Infra | resolved |
| OQ-2 | Where is **ComfyUI/provider config persisted** — extend `data/settings.json` (`DEFAULT_SETTINGS`), add a `ModelEndpoint` row variant, or a new small store? | Drives Slice 2/3/6 and whether Slice 6 settings work is needed at all. ComfyUI is not OpenAI-compatible, so a plain `ModelEndpoint` row may be a poor fit. | **`data/settings.json` / `DEFAULT_SETTINGS` first.** Add keys `media_models`, `default_image_media_model`, `comfyui_endpoint_url`. **No new database table yet.** | Infra + human | resolved |
| OQ-3 | Which ComfyUI **HTTP endpoints** does the target build expose for probe, queue, status, and retrieval? | The provider module and probe (Slices 3/4) depend on the exact API. | **Standard ComfyUI API defaults:** probe `GET /system_stats` (fallback `GET /object_info`); queue `POST /prompt`; poll `GET /history/{prompt_id}`; retrieve `GET /view`. | Human + Forge | resolved |
| OQ-4 | How are **workflows** supplied and parameterized? | Slice 4 generation flow + safety (R4). | **One bundled workflow JSON template with known field substitutions only.** No arbitrary user workflow loading in the first implementation. | Forge + human | resolved |
| OQ-5 | Which **generation entry path** should ComfyUI use? | Avoids owner-scope leak (R2) and duplicated logic; keeps the `generate_image` return contract intact (A5). | **Route ComfyUI through `src/ai_interaction.py` `do_generate_image()`** as the canonical owner-aware path. The MCP server must delegate to it rather than reimplementing. | Forge + Infra | resolved |
| OQ-6 | Does the existing `gallery_images` table cleanly hold **media metadata**? | Slice 5 (AC-8). | **Reuse existing gallery metadata fields first.** If provider/workflow/seed metadata does not fit cleanly, use a **JSON sidecar** beside the generated image for MVP. Do **not** add DB columns unless a suitable metadata field already exists. | Infra + Forge | resolved |
| OQ-7 | Should there be a **unified degraded-state response shape**? | Consistency/UX (R5, AC-3). | **Yes — one small degraded-state response shape**, reused by `list_media_models` and `generate_image`. | Architect + Forge | resolved |
| OQ-8 | Polling/timeout for `generate_image`? | Long jobs can stall the agent loop (R3). | **Bounded polling:** default max wait **120s**, poll every **1–2s**, emit progress via existing `progress_cb` if available. | Forge + human | resolved |
| OQ-9 | Is **Slice 6 (settings UI) required** for MVP? | Brief marks Slice 6 "only if needed"; forbids broad CSS/UI changes. | **Defer settings UI.** Configure through settings/default config first; backend/tool flow comes before UI. | Human + Prism | resolved |
